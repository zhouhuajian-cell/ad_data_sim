# BEV 三模块落地修订：当前版本补丁、真实帧验证、质量样板交付

日期：2026-11-21。此文补充并修正 `BEV三模块实拍合成_质量与PR提升_代码实施方案_20261120.md`。

## 1. 对上一版交付的纠正

上一版是架构方案、部分可运行基础模块和接入建议的组合，不是完成联调的生产实现。它没有把各入口的依赖、模块专用 QC、UE 捕获、真实标定和数据出口接线做成完整交付包，开发者容易只复制片段就认为功能已经实现。

本次提供两种明确区分的交付：

1. **现在可审查的候选补丁**：基于读取到的服务器当前源文件生成，带基线哈希、原始快照、完整候选文件、差异和测试。只解决已确认的运行/标签/状态缺陷。
2. **质量样板任务单**：明确每一项需要的真实输入、修改位置、输出和验收。只有做完这些并跑训练，才能评价逼真度与 P/R。

本次没有上传补丁、部署、重启服务或启动服务器生成任务。服务器已有原始 EXR 被只读复制/解码，用于本地真实帧后处理验证。

### 3.1 这批补丁刻意不冒充的能力

- `training_eligible=false` 是过渡状态：当前数据还没有真实标签完整合并、BEV 标定与多相机时序验收。完成这些后应由独立交付检查器决定资格，不能仅手工把字段改 true。
- 新增 `REVIEW/REVIEW_REQUIRED` 状态需要页面/导出端配套展示。现有页面未配套前，不切为线上默认链路。
- 目录重用现在明确拒绝，避免残留产物混入。真正的断点续跑需要逐帧 manifest/hash 管理；本补丁没有伪装成已实现断点恢复。
- 当前 legacy `post` 子命令仍有旧汇总逻辑，候选发布只验证 `run` 与直接 `obj_post.py`；该子命令不得作为生产交付入口，后续接线时统一。
- 亮度法掩码仍可用于外观调试，但框和遮挡率不应作为精确真值。原遮挡率数值仅保留为 unverified proxy。
- 本补丁不改变 OBJ 资产、相机、光照，不宣称图片变得更真实。

## 5. 下一阶段必须交付一个完整质量样板

不要再用“增加若干字段/脚本”作为完成标准。下一阶段交付物是一组可回放、可训练适配、可逐项检查的完整场景：

- 一个具备真实相机标定和原始标签的真实 clip，包含训练网络实际使用的所有相机和时序窗口。
- 一块可跟踪的限速牌、一个锥桶、一个车辆实例、一段实线/虚线。
- 在统一世界坐标生成 edits，在所有相机和时间戳投影；原有真实目标标签完整保留。
- 每项输出原图、合成图、ID/深度/可见 mask、最终标签、配置与质量记录。
- 并排展示旧版和候选版，记录接地/透视/颜色/阴影/时序错误，不仅展示缩略图。

先限制为白天、干燥路面、可靠标定。复杂夜景、雨天、透明材质、复杂坡道作为后续独立测试集扩展。

### 5.1 必须提供的输入

| 输入 | 来源与检查 | 缺失时处理 |
|---|---|---|
| 相机 K、畸变、相机外参 | 原采集/训练数据标定；检查分辨率及变换方向 | 不允许用 `est_camera.py` 猜测结果作为 BEV 真值 |
| ego pose、各相机时间戳 | 原训练数据；校验插值区间和不同步 | 只能做静态/2D研究，不标成时序 BEV 成品 |
| 原始完整对象/车道标签 | 已审核数据集；明确 ignore/crowd 语义 | 补标；未经审核检测结果不能冒充完整 GT |
| 地面/局部深度 | 标定地面、点云或可靠几何 | 人工标定小范围可放置区域；不扩大到未知区域 |
| 资产清单 | 真实尺寸、轴向、原点、材质与部件关系 | 可导入不等于可用于训练；先做资产检验 |

如果训练是相机+LiDAR/radar融合，还必须补齐相应模态；不允许只改图像而保留穿透合成目标的点云作为无冲突训练样本。

## 6. TSR 质量任务卡：轨迹一致的牌面替换

修改位置：`batch_walk.py / render_selected.py` 中素材选择和目标关联；提取共享 `render_tsr_target(scene, track, camera, timestamp)` 接口；旧 `paste_v2` 预览改调用同一接口。

执行顺序：

1. 以真实标牌 track ID 绑定替换目标，素材只选择一次。将素材 ID、限速值、国家、形状和变体记录到 scene edit manifest。
2. 按牌面世界平面计算每相机/时刻的四角投影；同一时刻跨相机一致。若只有人工二维四角，该样本不算 BEV 世界几何已验证。
3. 合成掩码限制在被替换牌面，原支架、底板和遮挡不变。组合牌需明确父底板/子牌关系。
4. 分别对齐白底、红圈、黑字；估照明时排除原数字，避免把旧语义纹理回贴。
5. 用上一版文档中的预乘 alpha 变换/线性合成模块做原尺寸输出；模糊按相机配置标定。
6. 最终标签绑定真实 track ID，使用素材类别和值；小目标只降低细属性监督，不删除检测监督。

交付验收：

- 同一牌在所有可见帧始终是同一个值；禁止本次看到的 60/60/10 跳变。
- 原牌框与精修框变化不会产生双标签。
- 有遮挡时合成纹理不覆盖前景；没有残留旧边、旧数字。
- 每个实际修改像素都落在允许的编辑/成像作用区域。
- 正常、小牌、斜牌、组合牌各有固定回归例，不只测最容易的样本。

## 7. OBJ 质量任务卡：先锥桶，再车辆

修改位置：`modules/obj.py` 资产适配、`demo_obj_v4.py` 捕获、`obj_post.py` 合成与标签。

### 7.1 资产接入不是填写一个 mesh 名称

当前 FBX 车辆存在 body/wheel 拆分，必须维护一个资产组装表：

```text
asset_id
parts: mesh_path / local_transform / material_slots
units / forward_axis / up_axis / ground_contact_origin
measured_size_m / bounds_definition / asset_version
```

先把一个锥桶和一辆车在纯色背景上转台渲染，检查所有部件是否齐全、轮子是否在正确位置、材质是否缺失、尺寸是否合理。必须在原生 3D 空间验收，不能靠后处理把缺轮子或白盒子修成车辆。

### 7.2 相机接入

- 取消生产路径的随机 camera/FOV，读取同一场景包的标定。
- 用固定棋盘板或带轴标记的立方体，选近中远三个位置；验证引擎像素投影与公共投影函数一致。
- 坐标转换显式处理 UE 厘米/轴向与训练端米制/轴向；不用 Euler 角字段直接交换。
- 对不居中的主点和 fx/fy 差异，按实际标定配置投影；当前只设 FOV 的实现不能标为已支持。

### 7.3 渲染通道具体交付

由 UE 开发者在现有项目内增加独立 capture pass，交付一个可加载的材质/蓝图资产与调用适配器，而不是留一段无法验证的 API 示例。

首批限制每帧不超过 200 个合成实例，可使用自定义 stencil 的有效 ID 范围；0 为背景，同一物体全部零件用同一实例 ID。超过限制要明确报错，禁止模运算循环复用。

必须输出并逐通道验收：

| 通道 | 要求 | 检验例 |
|---|---|---|
| RGB | 明确 linear/sRGB、曝光固定、无重复 gamma | 灰阶/色卡与直通背景 |
| instance ID | 不受物体颜色影响；不被 TAA 混色 | 黑轮胎/黑车身仍完整；重叠物体有唯一可见 ID |
| coverage | 0～1 抗锯齿覆盖率，与分类 ID 分离 | 细杆边缘和远处锥桶无黑边 |
| depth | camera-Z、米制，不是 device depth | 已知距离立方体数值吻合 |
| amodal mask | 同姿态、同相机、无其他合成物遮挡 | 两锥桶前后重叠时分母稳定 |
| shadow | 明确受影地面、方向和透射比例 | 阴影不乘到前景真实车辆/行人 |

只有这些通道完成，才删除候选中的 `occlusion=null`，改由可见 ID 与 amodal mask 计算真实可见率。不能恢复亮度 proxy 并改个字段名就称完成。

### 7.4 第一组样板场景

固定同一背景，在道路可放置区域生成：近/中/远锥桶；一个与真实前景重叠的锥桶；一辆车；车后部分遮挡锥桶。顺序推进，每个场景同时查看俯视几何、原尺寸图片和 mask。

通过条件：无悬浮/穿插，比例与标定一致；真实前景正确遮住合成对象；新对象遮住原目标后原目标 visibility 标签同步变化；白车/黑车都不丢 mask。

## 8. GND 质量任务卡：先用平面投影跑通

第一阶段普通平坦路面标线不必启动 UE；调用公共投影模块，使用米制道路图案，按同一世界位置在每相机/时间戳投影。

执行顺序：

1. 确定路面平面和可信可编辑区域；相机标定来自真实数据。
2. 以 line ID 生成固定纹理，修正后的 wear 决定覆盖率，所有帧复用同一份图案。
3. 从原路面提取低频受光照变化和适当颗粒；排除旧白线、车辆和非道路区域。
4. 用预乘 alpha 做透视变换，保留真实阴影；不使用当前 Unlit Cube 作为最终像素来源。
5. 生成 world polyline、每相机投影、可见段和训练需要的 BEV raster；三者来自同一份几何。
6. 有旧标线时按“新增/替换”操作分别处理；未做旧线修复的区域禁止强行新增冲突标线。

实线、虚线、停止线分别交付：原图、合成图、覆盖 mask、磨损纹理、世界线、可见线、BEV 标签。坡道/起伏不满足平面假设时拒绝该路径，转道路网格方案。

通过条件：画面中线宽随距离自然变化；磨损在世界位置固定，连续帧不闪；车辆遮挡标线时图像和标签一致；虚线各段保持车道关系，不把段号当 lane ID。

## 9. 模型收益的具体试验单

训练负责人先冻结：各头 matcher、生产阈值、验证/测试集、训练步数、种子、类别/距离分桶和允许退化边界。参数不能在观察 test 结果后反复调整。

至少执行以下实验，使用相同训练预算：

| 编号 | 数据 | 用途 |
|---|---|---|
| R0 | 真实数据 | 基线 |
| R1 | 真实数据等步数重复采样 | 排除训练时长差异 |
| T/O/G | 分别加入一种合成 | 识别哪个模块带来收益或副作用 |
| ALL | 加入三模块 | 检查 BEV 联合训练的负迁移 |

先试合成 batch 占比 5%、10%、20%，在真实 val 选择；候选至少三种训练种子复核。按 source scene 划分，合成变体和相邻帧不能跨 train/val/test。

必须报告：

- 固定 P 下 R，固定 R 下 P，锁定生产阈值下 P/R。
- TSR 检测与限速值/细类分别统计；OBJ 按类/距离/遮挡统计；GND 以正式线匹配和拓扑指标统计。
- 误报密度、困难样例回归、真实测试各头退化。
- 合成数据入训练前后，标签错误率、类别/距离覆盖、每场景独立样本量。

交付判据由业务指标填写，不能把“产出了 1000 张”或“检测器全通过”作为模型收益证明。

## 10. 平台接线必须在发布前完成

本候选包没有改 `server.py/index.html`，因此不得宣称页面已经支持新状态。

- API 返回 `generated/review/approved/failed` 四种数量，不能都叫成功数。
- OBJ `REVIEW_REQUIRED` 显示“生成完成，待质量复核”，非“渲染失败”；训练导出只读批准数据包。
- 所有预览/批量入口调用同一模块适配器、同一 schema 和有效参数集合。
