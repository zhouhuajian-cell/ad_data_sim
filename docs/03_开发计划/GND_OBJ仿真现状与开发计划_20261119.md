# GND 与 OBJ 仿真现状及开发计划

核对时间：2026 年 11 月 19 日。以服务器 `10.2.248.34` 的代码、接口和产物为准。TSR 已冻结，后续重点为 GND 和 OBJ。

## 一、当前结论

OBJ 和 GND 已跑通固定三帧小样：UE 加载验证关卡，生成几何代理和 RGB 图像，投影几何框并输出标注。网页可运行小样、查看抽检图和下载标注。当前能力适合验证链路；正式模型、真实参数下发、像素级标注和生产级批量调度仍需开发。

## 三、OBJ 现状

### 已实现

服务器定义轿车、SUV、货车、行人、锥桶、护栏的尺寸和语义值，使用 Cube、Sphere、Cylinder、Cone 组成代理物。真实模型路径 `ASSET_HINTS` 当前为空。

网页提供三个固定预设：车辆、行人和锥桶组合；单辆卡车代理；道路施工组合（卡车、锥桶、地面标线）。脚本固定三处相机位姿，输出 960×540 RGB、逐帧 JSON、PNG 成品、叠框抽检和 OBJ 的 COCO 文件。

服务器已有可复核的结果：

- `/data/render/obj_smoke.2HJ4pu`：车辆、行人、锥桶组合。此前检查为 3 帧、9 个 COCO 框。
- `/data/render/obj_smoke.QyuN96`：卡车代理 3 帧；导出类别为 `vehicle`。
- `/data/render/obj_smoke.Tz4GWd`：施工组合 3 帧；首帧 JSON 同时包含 `vehicle`、`cone`、`road_edge_white`、`lane_dashed_white`。`scene_annotations.json` 保存混合场景逐帧数据。

小样按实际生成的代理部件获取包围盒并投影，再生成 2D 框。当前可证明这些示例有输出；不同朝向、遮挡和截断情况下的准确度还需系统验收。

### 尚未完成

1. 正式卡车、车辆、人形和障碍物模型、贴图与素材许可管理。
2. 网页上的种类、数量、距离、位置、朝向等参数到 UE 的完整下发。当前预设为固定脚本，不应将未接入控件视为已生效。
3. 货车、轿车、SUV 的训练标签口径。小样将 `car` 和 `truck` 均映射为 `vehicle`。
4. 像素级遮挡比例与实例掩码；当前框面积重叠只能作为近似，需记录计算方法。
5. 可恢复的正式批量任务、资源调度、失败重试与版本化数据集。

## 四、GND 现状

### 已实现

`gnd.py` 定义白色实线、白色虚线、黄色实线、双黄线、停止线、斑马线、白色道路边线。标线由贴地薄几何体及材质构成，虚线拆成多个段。

现有 GND 小样固定包含白色边线、白色虚线、黄色实线和停止线。`/data/render/gnd_smoke.FLFJIi` 已生成 3 帧，首帧包含 5 个标线分段投影框、PNG、逐帧 JSON、`ground_annotations.json` 和抽检拼图。停止线曾出现方向错误，脚本已显式设置水平旋转并重跑。

### 尚未完成

1. 导出车道线中心线、边界线、像素语义或实例掩码；目前交付的是**几何分段的 2D 投影框与 JSON**。
2. 与道路区分的语义值。当前 GND stencil 与 road 共用 `1`，需要根据标签体系重设并验证像素值。
3. 双黄线、斑马线、不同视角和尺寸的实机验收。
4. 网页线型、磨损、反光、积水等参数下发。模块内部分参数已有代码，当前固定小样未接入这些网页控件。
5. 正式道路几何、路面材质、标线纹理及相机标定。

## 五、混合场景与共享限制

施工预设把 GND 标线和 OBJ 卡车、锥桶放在同一帧。下载 COCO 用于现有 OBJ 检测类别；完整场景 JSON 保留标线类别。现有 COCO 类别表不覆盖 GND 线型，不能把它视为完整的车道线数据集。

系统流程：网页提交作业 → 服务调用小样脚本 → `xvfb-run` 启动 UE → 生成 RGB 和真值 → 后处理成 PNG → 导出标注和抽检图。小样用文件锁避免 OBJ/GND 小样并发，但其他 GPU 业务仍需要统一调度。

作业状态主要保存在服务进程内，服务重启后历史作业追踪不足。服务器曾出现 Vulkan `VK_ERROR_DEVICE_LOST`。必须保留 UE 日志，分别检查进程退出、脚本异常、实际图片和标注；文件存在或退出码为 0 不能单独证明数据正确。

EXR 和 PNG 需要按实际编码、色彩空间和位深记录。小样 manifest 曾记 EXR 位深 16，而 OpenCV 后处理读回数组为 float32；需要区分文件通道存储类型和解码数组类型，不能仅根据当前字段确认实际精度。深度和语义材质需另做像素标定。

## 六、已知数据与契约问题

| 问题 | 影响 | 开发方向 |
|---|---|---|
| 旧 `/data/queue/tasks.jsonl` 仍含 `/Game/Maps/road_straight` | 与当前验证关卡不一致 | 生成新批次，校验关卡和资产 |
| 旧 `mod2_0000.json` 的 `objects` 为空 | 场景中目标未必进入逐帧真值 | 建立场景实例与帧级标注关联 |
| OBJ 细分类与导出 `vehicle` 映射不完整 | 训练数据类别丢失 | 统一类别表并保留细分类 |
| GND 类型不在现有 COCO 类别表 | 混合场景 COCO 不含完整标线 | 明确中心线、边界线、掩码及输出格式 |
| 世界单位和相机坐标需要统一 | 可能出现尺度或投影误差 | UE 使用厘米，导出单位明确，以已知距离验证 |
| 遮挡率使用框重叠近似 | 不能作为真实像素遮挡率 | 标记算法来源，后续接实例掩码 |
| 状态与文件缺少持久关联 | 重启和重试不易追溯 | 记录作业、运行参数、帧和产物的 ID 与状态 |

## 七、产品操作流程目标

1. 导入并管理正式 OBJ 模型、纹理及来源；选择道路和 GND 标线。
2. 设置目标类别、数量、位置、朝向、标线规格和相机，保存参数快照。
3. 生成单帧 RGB，叠加 OBJ 框和 GND 标线进行检查。
4. 先生成 3–5 帧，核对类别、位置、遮挡、日志和标注文件。
5. 按范围和随机种子提交批量任务，查看进度、失败和重试。
6. 抽检后导出带版本、类别表及参数记录的数据集。

## 八、后续开发优先级

**P0 稳定预览与小批。** 统一引擎、关卡、日志和成功判定，确保当前作业显示其对应结果；空图、缺帧、缺标注应明确失败。连续三次各跑 3–5 帧，检查图片非黑、目标可见、标注与图像对应。

**P1 OBJ 模型与参数。** 接入至少一辆真实卡车和一种障碍物，验证尺寸、朝向、原点和贴图；网页可下发数量、位置、朝向和 seed。以不同角度、遮挡和截断核对真实目标框及类别。

**P2 GND 标注。** 先与训练侧确定折线、边界、语义掩码、实例掩码的需求；实现线型、宽度和位置下发，并以多视角图像验证对齐。框保留作辅助抽检。

**P3 联合场景与批量。** 实现施工卡车、锥桶、道路标线与占道关系组合；持久化作业、调度和产物，完成取消、重试、续跑与版本化导出。先验收 20 帧，再扩大规模。

## 九、待业务确定

- 首要训练任务是障碍物检测、车道线检测，还是施工占道联合识别。
- 货车与轿车是否独立类别；车斗内锥桶是否逐个标注；护栏是否独立类别。
- GND 需要中心线、左右边界、语义掩码还是实例掩码，以及期望格式。
- 可用素材及许可、道路场景、相机分辨率和标定数据。
- 首批数量、工况比例、难例定义和质量验收标准。

## 十、如何试用已有能力

访问 `http://10.2.248.34:8010/`，选择顶部 OBJ 或 GND，在工具栏选择现有预设并运行三帧。UE 初始化可能需要几分钟，完成后看中央抽检图和下载标注，失败时查看日志。

```bash

bash /data/avsynth/ObjSmokeTools/run_obj_smoke.sh obj truck
bash /data/avsynth/ObjSmokeTools/run_obj_smoke.sh obj workzone

```

每次输出目录由脚本打印。正式批量前应验收图片和标注，并使用新生成且经过校验的任务清单。
